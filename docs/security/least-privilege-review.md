# Least-privilege and secret-exposure review (A6)

Reviewed 2026-10-30 against `main`, the live environment, and the released images.
Criterion A6: *service, CI/CD and cloud identities use least privilege; secrets are not
present in Git, images, browser bundles or logs.*

## 1. Cloud identities (AWS IAM)

| Identity | Used by | Permissions | Scope limits | Verdict |
|---|---|---|---|---|
| `techbleat-external-secrets` | External Secrets Operator (Pod Identity) | `secretsmanager:GetSecretValue`, `DescribeSecret` | Only `techbleat/cluster/*`; trust bound to one service account (`external-secrets/external-secrets`) | Least privilege. Cannot read `techbleat/identity/*` or the TLS backup |
| `techbleat-aws-load-balancer-controller` | LB controller (Pod Identity) | Upstream v3.6.2 policy ([file](../../infra/cluster/policies/aws-load-balancer-controller.json)) | One service account (`kube-system/aws-load-balancer-controller`) | Broad by design (it manages ELBs and SGs); vendor-maintained and version-pinned |
| `techbleat-ebs-csi` | EBS CSI driver (Pod Identity) | AWS managed `AmazonEBSCSIDriverPolicy` | One service account | Vendor-maintained |
| EKS node role | Kubelet, VPC CNI | EKS worker, CNI and ECR read-only policies (module defaults) | Pods cannot use it: IMDSv2 required with a hop limit of 1 | Acceptable |
| `techbleat-keycloak-execution` | ECS agent (Keycloak task start) | `AmazonECSTaskExecutionRolePolicy`; `GetSecretValue` | Secrets: only the listed `techbleat/identity/*` ARNs | Least privilege |
| `techbleat-keycloak-task` | Keycloak container | `ssmmessages:*Channel` (ECS Exec for operator port forwarding) | No AWS data access | Least privilege |
| `techbleat-datadog-integration` | Datadog's AWS account | Read-only: CloudWatch metrics, tags, describe RDS/ElastiCache/ECS/ELB | Trust requires Datadog's account **and** an external ID (confused-deputy protection); no write or data-read actions | Least privilege |
| Operator (IAM user) | Terraform, scripts | Administrator | Long-lived access key on one laptop | **Gap**: production would use SSO with short-lived roles and separate plan/apply roles |

Cluster API access uses EKS access entries only (no `aws-auth` ConfigMap). Only the
Terraform identity is a cluster admin. The public endpoint is restricted to the operator's
IP (`admin_cidrs`, /32).

## 2. Kubernetes and mesh identities

| Control | Detail |
|---|---|
| Service accounts | One per workload. `automountServiceAccountToken: false` on every banking workload and the db-init Job: no app pod can call the Kubernetes API |
| Mesh identity | Istio SPIFFE identity per service account. AuthorizationPolicies allow each caller only the paths it needs (deny by default) |
| Database roles | Per service, minimal grants ([db-init.yaml](../../deploy/data/db-init.yaml)): user-service `SELECT, INSERT` on users and `INSERT` on accounts; transaction-service `SELECT, UPDATE` on accounts and `SELECT, INSERT` on transactions; activity-service `SELECT, INSERT` on activities. No `DELETE`, no DDL. The master credential exists only in the `banking-admin` namespace |
| Kafka | Per-service TLS client certificates. ACLs: transaction-service may only write `transactions`; activity-service may only read it with its own group |
| Keycloak clients | `banking-frontend`: public, PKCE, exact redirect URIs. `user-provisioner`: service account limited to `realm-management/manage-users` on the banking realm (no realm admin, no client or realm settings). Live test: another service's token is denied the admin API (`403`) |
| Argo CD | `banking` project: this repository only, three namespaces, **no cluster-scoped resources**, no quotas or limit ranges. `platform` project: pinned upstream chart repositories |

## 3. CI/CD identities

| Control | Detail |
|---|---|
| Default token | Workflow-level `permissions: contents: read` |
| Image job | Adds only `packages: write` (GHCR), `id-token: write` (keyless Cosign, provenance) and `attestations: write`. Push, signing and attestation steps run only on `main`, tags or manual dispatch; pull requests build and scan without publishing (and pull requests from forks receive a read-only token) |
| Cloud credentials in CI | None. CI cannot reach AWS or the cluster. Argo CD pulls from Git (pull-based GitOps) |
| Third-party actions | Pinned by full commit SHA |
| Signing keys | None to steal: keyless signing tied to the workflow identity |

## 4. Where secrets live

| Secret | Location | Who can read it |
|---|---|---|
| DB role passwords, Valkey token, provisioner client secret, Keycloak CA | Secrets Manager `techbleat/cluster/*` (generated by Terraform) → Kubernetes Secrets (KMS-encrypted) | External Secrets; the consuming pod |
| DB master password | `techbleat/cluster/db/master` → `banking-admin` namespace only | db-init Job |
| Keycloak admin, DB and TLS key | `techbleat/identity/*` | Keycloak execution role only (not EKS) |
| Datadog API key | Operator env var → `techbleat/cluster/datadog` → `datadog` namespace | Datadog Agent |
| TLS certificate backup | `techbleat/tls-certificate-backup` (bootstrap) | Operator only |
| DuckDNS token, Datadog app key, alert email | Operator's local environment / git-ignored `terraform.tfvars` | Operator only |
| Terraform state (contains generated secrets) | S3 state bucket: private, encrypted, versioned, TLS-only policy | Operator only |

Nothing above is in Git. Generated secrets change on every `up`. Rotation is covered by the
[runbook](../runbook.md#rotate-credentials).

## 6. Log review

| Check | Result |
|---|---|
| Application code | Tokens and passwords are never logged. `security.audit` events record the reason (`authentication_failed`, `authorization_denied`), the path and the client IP only |
| Live cluster logs after forged-token and cross-account tests | No token or password values found |
| Datadog (logs leave the cluster) | Agent processing rules mask bearer tokens, JWTs and `password`/`secret` fields. A JWT sent in a URL arrived as `[REDACTED_JWT]` ([evidence](../evidence/phase5-observability.md#no-secrets-in-telemetry-a10)) |
| Keycloak (ECS) | Logs go to CloudWatch; Keycloak does not log credentials. Admin events are kept in the realm |

## Findings and follow-ups

| # | Finding | Severity | Action |
|---|---|---|---|
| 1 | Operator uses a long-lived admin access key | Medium | Move to IAM Identity Center with short-lived roles; separate read-only `plan` and `apply` roles |
| 2 | The provisioner's `manage-users` can assign any banking realm role | Medium | Keycloak fine-grained admin permissions limited to `banking-customer` |
| 3 | Argo CD `platform` project allows any cluster-scoped kind | Low | Expected for platform controllers. Restrict to the listed CRD groups if more teams are added |
| 4 | LB controller policy is broad (vendor policy) | Low | Add `elbv2.k8s.aws/cluster` tag conditions (upstream supports them) |
| 5 | Old dev password in history | Low | Treated as compromised; never reused |
